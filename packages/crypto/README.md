# @chronos/crypto

Envelope encryption for health fields and other confidential data (CLAUDE.md rule 5). No custom primitives: AES-256-GCM from `node:crypto`, key wrapping by AWS KMS.

```ts
import { KmsKeyWrapper, SubjectKeyring } from '@chronos/crypto';

const keyring = new SubjectKeyring({
  wrapper: new KmsKeyWrapper({ keyId: config.KMS_KEY_ID }),
  store: wrappedKeyStore, // backed by the vault's subject_keys table
  ledger: erasureLedger, // ADR-0014
});

const sealed = await keyring.encrypt(vaultId, 'payload', { conditions: [...] }); // { ciphertext, nonce }
const value = await keyring.decrypt(vaultId, 'payload', sealed); // unknown: validate with zod
await keyring.shred(vaultId); // crypto-shred
```

- **Per-subject data keys**, generated by KMS `GenerateDataKey` and stored wrapped. The KMS encryption context binds each key to its subject and purpose.
- **AAD** binds each ciphertext to subject, field and format version, so ciphertext copied to another row or field fails to decrypt.
- **Random 96-bit nonces**; the 16-byte tag is appended to the ciphertext. The per-subject key keeps encryption counts far below GCM limits.
- **Key cache** holds plaintext keys at most 60 seconds, zeroes them on eviction (best effort in JavaScript), and can be disabled (`cacheTtlMs: 0`).
- **Errors are generic** (`DecryptionError`, `KeyDestroyedError`, `KeyUnwrapError`) and never carry keys, plaintext or ids.
- **Provider-neutral:** implement `KeyWrapper` to move off AWS KMS (ADR-0011).
- **Tests:** `@chronos/crypto/testing` provides in-memory doubles (refuses production). `pnpm test:integration` runs the KMS tests against LocalStack via Testcontainers (needs Docker).

Not in this package: the erasure ledger store and restore replay (M2.7), and re-encrypting a subject's data under a new data key (needs a vault transaction; M2.x).
